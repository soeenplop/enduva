# 07 — Risks

| # | Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- | --- |
| R1 | **TypeScript 7 tooling gaps.** No JS compiler API in TS 7.0, so decorator metadata emit and typescript-eslint may not work | High | High | Spike 0.3 before any feature work, with hard CI acceptance criteria (see architecture): SWC directly for NestJS emit (no Nest CLI), TS 7 `tsc` for type-checking, lockfile audit against pre-7 compilers, Zod-based OpenAPI (no Nest compiler plugin), oxlint instead of typescript-eslint, oxfmt instead of Prettier, React instead of Svelte (`svelte-check` needs TS 6). No TS 6 as compiler, type checker, language service or emitter: if a blocker remains, the lead decides (W13). TS < 7 parser code that third-party tools bundle for formatting (Prettier via TanStack's route generator, oxfmt) is tolerated only on the bundled-TS allowlist, and a CI audit of the installed packages fails on any unlisted copy, and on any change of an entry's package version, detected bundled version, file digests or direct consumers (owner ruling on PR #97) |
| R2 | **App Store rejection** for Google login without Sign in with Apple (Guideline 4.8) | High (for App Store / external TestFlight) | Medium | Sign in with Apple is planned in Phase 0 (task 0.14) and checked in gate G2 |
| R3 | **HealthKit limitations**: data only on device, background delivery is throttled, route/stream data is heavy | Medium | Medium | Anchored queries + background delivery (system-scheduled, verified on a real device) + complete foreground catch-up. Re-import of late-arriving routes/samples. Compressed stream upload. Resumable sync |
| R4 | **AI nutrition accuracy** (portion sizes from photos are hard) | High | Medium | Clarifying questions, editable gram amounts, matching to real DB entries, "AI estimate" badge, nothing logged without confirmation, fixture set to track quality over time |
| R5 | **AI cost & abuse** with open registration | Medium | Medium | Consent + per-user quotas + global kill switch, Turnstile at sign-up, email confirmation, `ai_usage` monitoring |
| R6 | **GDPR / health data** (Art. 9) | Medium | High | **Gate G1** before any real health data: legal basis + explicit consent, DPIA screening, working export/deletion incl. Storage and queued jobs, deletion-aware restores, provider retention terms, real privacy policy. Synthetic data only in all environments until then, and production sign-up locked from its first exposure. EU hosting, data minimisation for AI, "not medical advice" disclaimer |
| R7 | **Food data licences & quality** (OFF ODbL share-alike, OFF data gaps, BLS CC BY attribution) | Medium | Medium | OFF kept as an independent dataset (own tables, composable search), ODbL attribution + offer page for adapted OFF data, BLS attribution naming the Max Rubner-Institut, data-sources page before G1, quality score per item |
| R8 | **Supabase free-tier limits** (500 MB, pausing, no backups) | Medium | Medium | Store streams compactly, import only a DACH OFF subset, upgrade prod to Pro at G1 (T13a), own nightly dumps |
| R9 | **Sync conflicts / data loss** between Watch, iPhone and server | Medium | High | Sync contract (ADR-0004): idempotent mutations, commit-ordered change feed, base-version conflicts instead of blind LWW, delete-wins tombstones with retention + full resync, single HealthKit save authority. Dedicated concurrency test suite |
| R10 | **Agent workflow overhead** (review loops, merge conflicts between parallel PRs) | Medium | Low | Small PRs, max 3 parallel implementers, serialise migrations/contracts, arbiter rule after 2 rounds |
| R11 | **Single GitHub identity** for all agents (authorship unclear, no formal approvals) | Certain | Low | `[Sol]`/`[Claude]`/`[Astra]` prefixes, head-bound verdicts, `--match-head-commit` merges, ruleset for PRs + status checks. Optional bot account / GitHub App later |
| R12 | **Signing key without passphrase** on the owner's machine could be copied and misused | Low | Medium | Signing-only key (not an auth key), file mode 600, configured only for this repo. **Residual exposure:** a copied key can sign commits in any repo under the owner's GitHub identity, and GitHub keeps existing "Verified" records after a key is removed. **Compromise response** (`docs/runbooks/signing-key.md`): remove the key from GitHub, generate and register a new one, audit every commit signed with the old key during the exposure window (`git log --show-signature`, GitHub search across the owner's repos), revert or annotate suspicious commits. Agents report signing failures instead of disabling signing |
| R13 | **Public repo leaks** (secrets, personal data in fixtures) | Low | High | Gitleaks, `.env` ignored, synthetic fixtures only (no real health data of the owner in the repo) |
| R15 | **Training-load and VO2max accuracy** without power meters (HR-based load depends on thresholds; own VO2max estimates are rough) | Medium | Medium | Method and estimate labels on every value, Apple VO2max preferred, auto-estimated thresholds with user override, recomputation on threshold changes, reference-example unit tests, "not medical advice" disclaimer |
| R16 | **OpenFreeMap availability** (free public service without SLA) | Medium | Low | Style URL is runtime config. Documented switch to self-hosted Protomaps PMTiles or MapTiler. Map failure degrades gracefully (activity data still shown) |
| R17 | **Single environment before G1** (no staging): every merge reaches production directly | Medium | Low | Production holds synthetic data only until G1. Every push is verified in the isolated candidate environment before deploy. Staging + release-gated production are introduced in G1.6, before any real data |
| R14 | **Scope creep** (three apps in one) | High | High | Strict phase exit criteria. Backlog for everything "later". Scope changes go through reviewed PRs to this plan; the owner sets direction and can veto any PR |
