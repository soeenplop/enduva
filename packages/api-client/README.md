# @enduva/api-client

Typed fetch client for the Enduva API, generated by [Orval](https://orval.dev) 8.49.0 from the committed
[`apps/api/openapi.json`](../../apps/api/openapi.json) ([ADR-0001](../../docs/adr/0001-typescript-7-toolchain.md):
Orval prints code itself and needs no `typescript`). One function per operation (`getHealth`, `getReadiness`,
`getMe`, `updateMe`) and the schema types (`Me`, `MeUpdate`, `Problem`, …).

`pnpm generate` writes `src/generated/api.ts`. Turbo runs it after `@enduva/api#generate`, before build, typecheck,
lint and test. The output is git-ignored, so it can't go stale; it is type-checked with our strict flags but not
linted or formatted. There is no React Query output (ADR-0001 pitfall 2): the web app writes `queryOptions` around
these functions.

```ts
const res = await getMe({}, { baseUrl, accessToken });
if (res.status === 200) use(res.data, res.headers.get('ETag'));
else if (res.status === 401 && res.data.code === 'device_revoked') wipeLocalData();
```

Every call goes through the mutator [`src/fetcher.ts`](src/fetcher.ts), which takes everything per call (base URL,
the user's access token as `Authorization: Bearer …`, an optional `fetch`) and keeps nothing in module state, so one
SSR process can serve several users at once. Errors are not thrown: the result is `{ data, status, headers }`, and
`status` narrows `data` to the documented body, which it always is:

- A `304` to a `GET` or `HEAD` has no body.
- `200` carries its parsed JSON object (not validated against the schema). Without a JSON object body (empty,
  malformed, `null`, an array or a primitive), the call rejects with `ApiResponseError` (status only, no body).
- Every other status carries a `Problem`, because the generated types put every undeclared status there (a `204`,
  a `304` to a `PATCH`, an undocumented `201`). If the response has no problem body (a proxy's HTML page, malformed
  JSON, no body), the client makes one up with `code: UNEXPECTED_RESPONSE` (`'unexpected_response'`, never sent by
  the API) and the response's status, so `res.data.code` is always readable.

An operation that later declares another success status (`201`, `204`) must extend these rules in `src/fetcher.ts`.

So a call throws only on network failures, without `baseUrl`, and with `ApiResponseError`.
